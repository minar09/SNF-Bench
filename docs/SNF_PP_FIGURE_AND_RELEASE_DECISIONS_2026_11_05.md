# Journal figure and asset decisions

2026-11-05. Review of the draft's TikZ figures, saved frame provenance, interactive companions and Steady-Forcing release documentation. This record does not change frozen scores, videos or selected panels.

## Decisions

1. **Quality first.** Keep the lossless main-panel frames and vector diagrams for the working draft. The 37 MB PDF is acceptable for development; check the actual submission portal's limits at submission time. If compression is required, test printed and zoomed output before changing formats and retain original frames and hashes.
2. **Historical common configuration.** The seven 240 s checkpoint videos were produced under the original common T2V inference configuration, not necessarily each released native pipeline. The qualitative captions and results text now say this. These four historically inspected prompts and one seed per checkpoint are illustrative, not an unbiased ranking or new confirmation data.
3. **Interpret maps conservatively.** Pixelwise first/last appearance change does not isolate geometric camera drift; successive-frame change can include flicker, illumination and compression. The late map is a whole-window summary, not a temporally varying overlay and not proof of continued motion. The figures and viewer have been relabelled accordingly. The nominal 240 s frame is the last available frame, slightly earlier than 240 s for the current files.
4. **Routing and statuses.** Frozen means a versioned definition, not validated construct validity or headline admission. DLR and DAR are contextual; MCFF and FP require joint interpretation, not blind maximization. The routing diagram is schematic: DLR crosses roles and global compensation can use support information; planned scene integrity is not confined to a subject mask. The captions and interactive descriptions have been narrowed.
5. **Steady-Forcing.** Use the published `steady_forcing_t2v.pt` checkpoint and its released inference script as the reference configuration, pending a full revision, configuration, checkpoint hash and runtime audit. The [official Hugging Face file listing](https://huggingface.co/minar09/Steady-Forcing-T2V-1.3B/tree/main) lists `steady_forcing_t2v.pt`; the [official inference script](https://github.com/minar09/steady-forcing/blob/main/inference.sh) specifies `configs/self_forcing_dmd.yaml`, 300 output frames and `--use_ema`. The prose model card names a hyphenated filename, so do not infer identity from a similar filename. The local `/home/minar/static-forcing/inference_st.sh` instead points to `steady_forcing_st.pt` and `configs/steady_forcing_infer.yaml`; the local paper figure provenance labels `steady_forcing_bt` outputs as deployed-system outputs, but does not establish checkpoint-byte identity or full inference equivalence. Do not select either local 240 s family as released-checkpoint evidence until logs or hashes establish the relationship. Reuse a verified existing output, or generate only the missing verified cell after recording the exact release; do not insert an unverified row to complete the figure. The released 300-frame example alone does not establish a validated native 240 s configuration.
6. **I2V sources.** Do not publish a 48-image gallery based on undocumented licenses. The displayed source has attribution and a link to its source and CC BY 2.0 terms, with crop/overlay disclosed. Check original metadata and all downstream reproduction rights before final release.
7. **Repository assets.** Version the manuscript source, build scripts, asset manifest, and the actual curated figures and viewer assets needed to render and review this paper. Keep the high-quality images for now; do not add unrelated video files or all source footage. Git LFS is not installed in this environment; do not insert LFS pointers without a working distribution plan. Before publishing or committing, inventory rights for all reproduced/generated frames, remove or replace machine-specific absolute source paths in the public provenance manifest, and verify that a clean checkout can build and load all assets. No commit or push was made as part of this review.

## Verification and remaining work

* `SNAPSHOTS.json` lists the four prompt IDs, seven checkpoint keys, source video hashes and frame indices. The selection script sorts common prompt IDs; it does not independently establish when any images were first viewed. Say the selection rule explicitly rather than claiming retrospective proof of blindness.
* `scripts/build_journal_snapshots.py` assumes 16 fps and 832×480; it should validate actual frame rate, dimensions, timestamps, successful decode and exact selected-frame times before future regeneration. Its use of a shared fixed timebase and clamped last frame must be recorded in any new provenance manifest.
* The interactive pages are offline companions, not a substitute for readable paper figures. Their user-interface behavior, keyboard and touch access, local-file image loading, and layout still need an actual browser pass; source-level or simulated setup tests do not establish that.
* Figure colour distinctions in the heat maps and source-role overlay are not all redundantly encoded by shapes. Check grayscale, color-vision deficiency and print-size readability before submission rather than claiming universal shape redundancy.
* A PDF rendering review confirms the figures appear in the built document, but the overview's small role-map legend, timeline frames and status text, and the routing figure's labels, are tiny at two-column print size. Treat the present plates as working drafts: split or enlarge them and inspect actual printed size before submission. Larger image files alone will not fix small type.
* Real-footage and human validation, source licensing, independent annotations and held-out evaluation remain open. The new figures do not close those gates.
